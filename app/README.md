# rift_app · Android-клиент «Расселины»

Flutter (UI/UX) + Flame (боевая сцена) поверх пакета `rift` — чистого
Dart-ядра, лежащего в корне репозитория и подключённого по пути (`path: ..`).

**Правило, ради которого существует это разделение:** ни одной игровой формулы
здесь быть не должно. Вся математика живёт в `../lib/core` и остаётся
headless-тестируемой (`dart test`, `dart run tool/sim_cli.dart`). Клиент только
показывает то, что ядро посчитало.

Анализ переносимости, замеры и порядок работ — `../docs/05-ANDROID-PORT.md`.

## Запуск

```bash
flutter run -d android
```

Быстрый цикл разработки экранов — в браузере (перезагрузка секунды вместо
десятков). Целевой платформой веб не является: `compute()` там вырождается в
вызов на том же изоляте.

```bash
flutter run -d chrome
```

## Контент

Источник истины — `../assets/content/*.json`. Flutter не умеет объявлять ассеты
выше корня пакета, поэтому `assets/content/` — зеркало, которое надо обновлять
после каждой правки баланса:

```bash
dart run tool/sync_content.dart
```

## Что сейчас в `lib/dev/`

Дев-проба, а не заготовка UI. Она доказывает, что ядро крутится на телефоне без
правок: контент грузится из ассетов, спуск считается в фоновом изоляте, Flame
рисует поверх обычного Flutter-экрана. Игровые экраны делаются с нуля по
собственному UI/UX, а `lib/dev/` при этом удаляется, а не переиспользуется.
