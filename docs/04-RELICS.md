# Реликты

Реликт меняет **правило**, а не число. Поэтому каждый требует своей ветки в
симуляции: эффект без ветки валит загрузку контента — и это правильно, иначе
реликт выглядел бы рабочим и не работал.

Их двадцать пять. Восьми хватало на вечер.

## Правило слотов

Раньше валидатор требовал **не больше одного** реликта на вид снаряжения — это
было следствием того, что реликтов было ровно восемь, по числу слотов. Теперь
правило обратное: **каждый вид обязан иметь хотя бы один**. Два реликта на один
слот — это и есть решение игрока, какое правило ему важнее; а слот без
реликта — дыра, в которой сборка не может получить правило.

Одновременно надеть два реликта на один слот нельзя физически, так что «два
взаимоисключающих правила без указания, какое сильнее» не возникает.

## Как проверено

`dart run tool/audit_cli.dart --relics` прогоняет два одинаковых боя,
отличающихся только надетым реликтом, и сравнивает отпечаток с порогом
собственного шума. Правила спуска (волны, старт, боссы, добыча) проверяются
двумя спусками с одним сидом.

Каждому реликту нужен свой стенд — тот, где его правилу есть что делать:
живучести смертельный бой, правилам про способности четыре активки, горению
приглушённая автоатака, правилам про слоты заполненные слоты. Стенд без этого
объявляет мёртвым то, на что просто не смотрит.

Проверка закреплена тестом `test/content_audit_test.dart`.

## Две ловушки, найденные при проверке

**Индекс перечисления вместо номера слота.** Колец два, поэтому номера
расходятся начиная с амулета: в перечислении он седьмой, в снаряжении —
восьмой. Реликты амулета не надевались вовсе, и аудит показывал «ничего не
делает» там, где предмет просто не был надет.

**Стенд без заполненных слотов.** «Парным кольцам» нечего удваивать на голом
наёмнике, а амулет, который они выключают, не надет. Правило про слоты видно
только на слотах.
